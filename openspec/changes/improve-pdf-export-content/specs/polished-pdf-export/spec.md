## MODIFIED Requirements

### Requirement: PDF renders the analysis using print-specific React components

The PDF is generated by a server-side Lambda that uses headless Chromium (`puppeteer-core` + `@sparticuz/chromium`) to navigate to a print-optimised `/print/{analysisId}` route in the Next.js app, wait for the page to fully render, and call `page.pdf()`. The print route SHALL compose **print-specific React components** (under `frontend/src/components/print/`) rather than reusing the components that drive the live `/analysis/{id}` screen. Print components consume the same `AnalysisData` shape but render layouts optimised for paper: fully-expanded content (no collapse-by-default), no interactive UI chrome (no zoom/pan controls, no toggle buttons, no hover-only affordances), and page-friendly geometry (vertical stacks instead of horizontal flex rows where width is constrained). Design tokens (colours, typography, spacing) remain shared across screen and print so brand consistency is preserved.

#### Scenario: PDF includes the EBITDA tree fully expanded

- **WHEN** the analysis has a populated `ebitdaTree`
- **THEN** the rendered PDF includes the EBITDA tree visualisation showing every node at every depth in a single static rendering
- **AND** no interactive UI chrome (Fit / Expand / zoom controls, "Scroll to pan…" help text, or hover-only state) appears in the PDF
- **AND** the rendering does not require user interaction to reveal child nodes

#### Scenario: PDF includes the value chain without horizontal truncation

- **WHEN** the analysis has a populated `valueChain` with N primary activities and M support activities
- **THEN** the rendered PDF includes all N primary activities and all M support activities, each with its full label visible
- **AND** no activity row is cut off horizontally at the page edge

#### Scenario: PDF excludes sections that are missing data

- **WHEN** an analysis lacks a section (e.g., no opportunities, no EBITDA tree)
- **THEN** that section is omitted from the PDF without leaving an empty header or blank page

#### Scenario: Print components are decoupled from screen components

- **WHEN** a developer modifies a screen component (`RiskBreakdown`, `OpportunitiesList`, `EbitdaTree`, `ValueChainDiagram`)
- **THEN** the modification has no effect on the rendered PDF
- **AND** the print-specific components in `frontend/src/components/print/` are not imported by any non-print page

### Requirement: PDF supports per-section page-format overrides

The PDF SHALL default to A4 portrait for every page and SHALL allow specific sections (e.g., the EBITDA tree page) to override the page format using named `@page` rules in `print.css`. Sections without an override use the default. Section breaks SHALL respect:

- `page-break-inside: avoid` on opportunity cards, risk-score rows, and EBITDA outline blocks
- `page-break-before: always` between major sections (Cover → Executive Summary → Risk Profile → Opportunities → EBITDA → Value Chain → Methodology → Back Cover) when the previous section is short enough that the next would otherwise start mid-page
- No-orphan-headings: a section heading SHALL NOT appear at the bottom of a page with the body content overflowing to the next page

#### Scenario: EBITDA tree page renders on a wider page format

- **WHEN** the EBITDA tree section is rendered as part of the PDF
- **THEN** that section's pages use the `ebitda-page` named `@page` rule (A3 landscape)
- **AND** the surrounding pages (cover, executive summary, risk profile, opportunities, value chain, methodology, back cover) remain A4 portrait

#### Scenario: Multi-page PDF has a footer on every page

- **WHEN** a generated PDF is two or more pages long
- **THEN** every page after the cover renders the footer template with the page number and total pages
- **AND** the footer text matches the format "Page X of Y · sc0red.com"

#### Scenario: Cover page has no running header

- **WHEN** the PDF cover page is rendered
- **THEN** the page does not show the running header that appears on subsequent pages

## ADDED Requirements

### Requirement: PDF includes a one-page Executive Summary after the cover

The PDF SHALL render an Executive Summary section immediately after the cover page when the analysis has either `riskScores` or `opportunities`. The section is a single page composed of:

- An EBITDA-uplift bar (current → +revenue uplift → +cost reduction → target) derived from the top-level `ebitdaTree` margin / revenue / cost figures, when `ebitdaTree` is populated.
- The top three opportunities, each rendered as a one-line entry showing `{title} — {investment_range} · {timeline}`. Selection: sort `opportunities` by `impact_rating` (High > Medium > Low), then by original index; take the first three. If fewer than three exist, render whatever is present.
- The top three risk drivers, each rendered as `{category}: {first sentence of rationale}`. Selection: sort `riskScores` by score descending; take the first three.

If the analysis lacks both `riskScores` and `opportunities`, the entire Executive Summary section SHALL be omitted (no empty page).

#### Scenario: Analysis with full data renders the executive summary

- **WHEN** the analysis has at least three opportunities, three risk scores, and a populated EBITDA tree
- **THEN** the PDF page immediately after the cover is the Executive Summary
- **AND** the summary contains the EBITDA-uplift bar, three opportunity one-liners, and three risk-driver lines

#### Scenario: Analysis without opportunities or risk scores omits the section

- **WHEN** the analysis has zero opportunities and zero risk scores
- **THEN** the Executive Summary section is omitted entirely
- **AND** the page immediately after the cover is the next non-empty section

### Requirement: Risk Profile renders fixed-expanded rows with rationale text

The Risk Profile section SHALL render every entry in `riskScores` as a fixed-expanded row, sorted by score descending. Each row SHALL display:

- The category name
- The score as a numeric value AND as a fixed-width score bar coloured by tier
- The full `rationale` text as body copy below the score bar (NOT collapsed behind a chevron, toggle, or tooltip)

#### Scenario: Risk row shows rationale without interaction

- **WHEN** the risk profile section is rendered for an analysis with a `rationale` field on each risk score
- **THEN** every row shows the rationale text directly in the body of the document
- **AND** no chevron, expand button, or other interactive control is present in the rendered output

#### Scenario: Risk row without rationale renders the score bar only

- **WHEN** an individual `riskScores` entry has no `rationale` field
- **THEN** the row renders the category, score, and score bar
- **AND** no rationale paragraph is rendered for that row (no empty placeholder)

### Requirement: AI Opportunity Roadmap renders one expanded card per opportunity, grouped by value lever

The AI Opportunity Roadmap section SHALL render every opportunity as a fully-expanded card showing all populated fields: title, value-lever badge, impact rating, timeline, strategic category, full description, numbered list of implementation steps (when present), investment range, and ROI estimate. Cards SHALL be grouped by `value_lever` with section dividers in the order Revenue Side → Cost Side → Both → (no lever). Within each group, cards retain their original `opportunities` array index so that linkage references from EBITDA and Value Chain sections (using `linked_opportunity_indices` and `opportunity_indices`) point at the correct card.

#### Scenario: Opportunity card surfaces all populated fields

- **WHEN** an opportunity has `description`, `implementation_steps`, `investment_range`, and `roi_estimate` populated
- **THEN** the rendered card shows all four fields as visible text in the document
- **AND** no expand/collapse control is rendered

#### Scenario: Cards are grouped by value lever

- **WHEN** the analysis contains opportunities across multiple `value_lever` values
- **THEN** the cards are rendered in groups: Revenue Side first, then Cost Side, then Both, then any with no lever
- **AND** each group is preceded by a section divider naming the lever

### Requirement: EBITDA Impact Model renders statically with linkage callouts

The EBITDA Impact Model section SHALL render the tree statically as a nested HTML outline (label → value range → percent → children, indented) on a section-overridden page format (A3 landscape). The static rendering SHALL NOT include any interactive UI chrome (zoom controls, fit/expand buttons, pan-help text). The outline preserves parent-child relationships via indentation regardless of tree shape (balanced or unbalanced). Each branch SHALL include a "Linked opportunities" callout when its `linked_opportunity_indices` array is non-empty, formatted as `Opportunities: #{i} ({title}), #{j} ({title})`, where the indices reference the printed-PDF position of opportunity cards.

#### Scenario: Tree renders all nodes without interaction

- **WHEN** the analysis has an `ebitdaTree` with N nodes across multiple depths
- **THEN** every node at every depth is visible in the rendered PDF
- **AND** the visualisation does not require user interaction to expand subtrees

#### Scenario: Linked opportunities are surfaced per branch

- **WHEN** an EBITDA node has a non-empty `linked_opportunity_indices`
- **THEN** a "Linked opportunities" callout is rendered alongside that node
- **AND** each linked-opportunity reference shows both the index number and the opportunity's title

#### Scenario: Outline preserves hierarchy on unbalanced trees

- **WHEN** the EBITDA tree has unbalanced subtrees (one branch deeper or wider than another)
- **THEN** indentation makes each node's parent visually unambiguous
- **AND** every leaf is reachable from its root by following the indented chain

### Requirement: Value Chain Analysis renders as vertically stacked rows with linkage callouts

The Value Chain Analysis section SHALL render value-chain steps as vertically stacked rows (one row per step, full page width), with primary activities listed first followed by support activities. Each row SHALL display the step name, role description, risk-category chips, and a "Linked opportunities" callout when `opportunity_indices` is non-empty, formatted using the same indexing convention as the EBITDA section. The horizontal flexbox layout used by the live screen `ValueChainDiagram` SHALL NOT be used in the print path.

#### Scenario: All activities render fully without horizontal truncation

- **WHEN** the value chain has six primary activities and five support activities
- **THEN** every activity row is rendered with its full name, description, and chips visible
- **AND** no activity is cut off at any page edge

#### Scenario: Linked opportunities are surfaced per step

- **WHEN** a value-chain step has a non-empty `opportunity_indices`
- **THEN** a "Linked opportunities" callout is rendered for that step
- **AND** each linked-opportunity reference shows both the index number and the opportunity's title

### Requirement: PDF includes a Methodology Appendix

The PDF SHALL include a Methodology Appendix section before the back cover. The appendix occupies at most one page and contains:

- The source URL(s) the analysis was scraped from (from `companyUrl` and any other already-displayed source fields)
- The model and scoring rubric reference
- An AI-generated-content disclosure: "This report is generated by AI analysis of public information. Findings should be verified before acting on them."

The appendix SHALL NOT expose any field that is not already visible elsewhere in the live application.

#### Scenario: Appendix is rendered before the back cover

- **WHEN** any PDF is generated (regardless of analysis content)
- **THEN** the second-to-last page is the Methodology Appendix
- **AND** the disclosure text is present verbatim

### Requirement: PDF has a single sc0red CTA, on the back cover

The PDF SHALL include exactly one sc0red CTA, rendered on a dedicated back-cover page after the Methodology Appendix, when the analysis has at least one opportunity. The back-cover CTA SHALL contain the sc0red contact URL and a brief call to action. No other CTA SHALL appear elsewhere in the PDF — the in-component CTAs previously rendered inside `OpportunitiesList` and `ValueChainDiagram` SHALL be removed from the print path.

#### Scenario: Analysis with opportunities renders a single back-cover CTA

- **WHEN** the analysis has one or more opportunities
- **THEN** the rendered PDF contains exactly one sc0red CTA block
- **AND** that block is on the back cover page

#### Scenario: Analysis without opportunities omits the CTA entirely

- **WHEN** the analysis has zero opportunities
- **THEN** the rendered PDF does not contain any sc0red CTA
- **AND** the Methodology Appendix is the final page
