## Why

The screen rendering of the AI-generated strategy map (shipped in PR #239)
is a vertical stack of fully-expanded cards roughly 1,500–1,800px tall —
roughly 2–3 viewport-heights on a typical analysis. It pushes every other
section of the analysis page (Top Actions, Risk Profile, Opportunities,
EBITDA, Value Chain) below the fold, and visually dominates a page that
should let the buyer scan all dimensions of the analysis quickly. The
deep-dive CTA — the conversion engine — is at the bottom of the strategy
map and rarely seen without deliberate scrolling.

Beyond density, the current rendering doesn't *look like* a Kaplan & Norton
strategy map. The canonical artifact is a 2D diagram with four perspective
bands, theme columns, and cause-and-effect arrows running between
objectives. The data already carries the arrow set (5–12 hypotheses
generated by Step 7 of the pipeline) but they are never rendered. We're
producing the inputs of a strategy map and showing them as a long list.

## What Changes

- Replace `StrategyMapView`'s vertical-stack layout with a graphical
  2D map rendered via `@xyflow/react` (the same library already used
  by the EBITDA tree). Four horizontal perspective bands, objectives
  as compact chips, arrows drawn between them.
- Render the `arrows[]` data as first-class graph edges with hover
  popovers that show the `hypothesis` text. They were previously
  computed but never shown on screen.
- Reuse the EBITDA tree's hover-tooltip pattern for chip detail:
  default chip shows `id · short title · 8px confidence dot`; hover
  surfaces the full definition, the HIGH/MEDIUM/LOW confidence label,
  and the `rationale_source` if present.
- Compact the header band: vision rendered single-line (italic,
  truncate-with-tooltip), mission collapsed behind a `Mission ▾`
  disclosure, value-proposition rationale moved into the chip's
  hover tooltip.
- Compute theme-column placement using the data the schema already
  guarantees (Financial via `supports_financial_objectives`, Internal
  Processes via theme nesting); fall back to arrow-walking for
  Customer and Capacity perspectives that don't carry explicit theme
  membership in v1. Sparse-arrow fallback: place the chip in a
  shared-centre lane.
- Replace `WhatsMissingPanel`'s always-expanded gap rows with the
  click-to-expand-inline pattern used by `OpportunitiesList` and
  `ValueChainDiagram` (single-open accordion, `aria-expanded`,
  `aria-controls`). Default to collapsed.
- Move the `DeepDiveCTA` (headline variant) from below the strategy
  map to the top of `AnalysisDetail`, immediately under the export /
  delete action buttons. Strategy map's `WhatsMissingPanel` no longer
  has a CTA below it; the gaps still link the conversation but the
  conversion affordance is persistently visible at the top of the
  page.
- Print PDF view (`PrintStrategyMap.tsx`) is unchanged — paper has
  no scroll constraint and the verbose layout works there.
- Backend, JSON schema, Pydantic models, API serialisation, AI
  prompts: unchanged. This is a screen-rendering redesign only.

## Capabilities

### New Capabilities

- `strategy-map`: Screen rendering, layout, and interaction
  requirements for the AI-generated Balanced Scorecard strategy map.
  Captures the visual contract (graphical 2D layout, theme columns,
  arrows-as-edges) and the interaction contract (chip hover tooltip,
  edge hover popover, gap click-to-expand, header band disclosure)
  that PR #239 left implicit. Future redesigns or alternate surfaces
  (mobile-only view, embedded view) can refer back to this spec.

### Modified Capabilities

None. The existing `opportunities-cta-analytics` spec covers the
opportunity-CTA events (`sc0red_cta_banner_expanded`, etc.). The
strategy-map CTA events (`sc0red_cta_rendered_strategy_map`,
`sc0red_cta_clicked_strategy_map`) shipped with PR #239 were not
covered by any spec — they're being captured for the first time in
the new `strategy-map` capability above. The semantic relaxation
caused by the CTA's relocation (impression now means "page loaded
with a strategy map" rather than "scrolled to the strategy map")
is encoded as a requirement and scenario in that new spec, not as
a modification of the existing analytics spec.

## Impact

- **Frontend (heavy)**: `StrategyMapView.tsx` and `PerspectiveRow.tsx`
  are largely rewritten. `ObjectiveCard.tsx` is repurposed as a
  React Flow custom node mirroring `EbitdaNodeComponent.tsx`'s
  hover-tooltip pattern. `WhatsMissingPanel.tsx` adapts to the
  click-to-expand pattern. `AnalysisDetail.tsx` reorders to put
  `DeepDiveCTA` near the top.
- **New files**: `StrategyMapNode.tsx` (React Flow custom node);
  `strategyMapLayout.ts` (column-assignment + node/edge construction
  helper).
- **Backend**: no changes.
- **Schema / Pydantic / API types**: no changes.
- **AI prompts / corpus**: no changes.
- **PDF export**: no changes (`PrintStrategyMap.tsx` keeps verbose
  layout for paper).
- **Dependencies**: no new dependencies; `@xyflow/react` already in
  use for EBITDA tree.
- **Tests**: existing component tests (`StrategyMapView.test.tsx`,
  `PerspectiveRow.test.tsx`, `ObjectiveCard.test.tsx`,
  `WhatsMissingPanel.test.tsx`) all rewrite. New tests for the
  layout helper and the React Flow node component.
- **Visual regression**: the redesign is the point. Existing screen
  snapshots will need to be regenerated.
