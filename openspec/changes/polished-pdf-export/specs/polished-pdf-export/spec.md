## ADDED Requirements

### Requirement: Export PDF returns a binary PDF, not HTML

`GET /api/export/pdf/{analysisId}` SHALL return a binary PDF document with `Content-Type: application/pdf` and a `Content-Disposition: attachment` header carrying a sensible filename derived from the company name and analysis date. The current behaviour of returning HTML for the user to manually print is replaced.

#### Scenario: User clicks Export PDF on an analysis detail page

- **WHEN** the user clicks the Export PDF button
- **THEN** the response is binary PDF with `Content-Type: application/pdf`
- **AND** `Content-Disposition` matches `attachment; filename="{Company Name} - AI Risk Report - YYYY-MM-DD.pdf"`
- **AND** the browser triggers a file download (not a new-tab navigation)

#### Scenario: Filename sanitisation

- **WHEN** the company name contains characters that are invalid in filenames (slashes, colons, etc.)
- **THEN** they are stripped or replaced; the filename is at most 80 characters; UTF-8 is preserved via the `filename*` parameter

### Requirement: PDF renders the live analysis page via headless Chromium

The PDF is generated by a server-side Lambda that uses headless Chromium (`puppeteer-core` + `@sparticuz/chromium`) to navigate to a print-optimised `/print/{analysisId}` route in the Next.js app, wait for the page to fully render including charts, and call `page.pdf()`. The Lambda SHALL NOT use static HTML templates — every visual element comes from the live React tree, so charts, layouts, and design tokens stay in sync with the live application.

#### Scenario: PDF includes the EBITDA tree

- **WHEN** the analysis has a populated `ebitdaTree`
- **THEN** the rendered PDF includes the EBITDA tree visualisation as part of the document
- **AND** the visual representation matches what the user sees on the live `/analysis/{id}` page (subject to print-only layout adjustments)

#### Scenario: PDF includes the value chain

- **WHEN** the analysis has a populated `valueChain`
- **THEN** the rendered PDF includes the value chain analysis section

#### Scenario: PDF excludes sections that are missing data

- **WHEN** an analysis lacks a section (e.g., no opportunities, no EBITDA tree)
- **THEN** that section is omitted from the PDF without leaving an empty header or blank page

### Requirement: PDF has a cover page, page-numbered footer, and proper page breaks

The PDF SHALL begin with a cover page containing the company name, source URL, industry, overall risk score with tier badge, analysis summary, and generation date. Subsequent pages SHALL display a footer with the company name, page number ("Page X of Y"), and the sc0red brand. Section breaks SHALL respect:

- `page-break-inside: avoid` on opportunity cards, risk-score rows, EBITDA tree blocks
- `page-break-before: always` between major sections (Top Actions → Risk Assessment → Opportunities → EBITDA → Value Chain) when the previous section is short enough that the next would otherwise start mid-page
- No-orphan-headings: a section heading SHALL NOT appear at the bottom of a page with the body content overflowing to the next page

#### Scenario: Multi-page PDF has a footer on every page

- **WHEN** a generated PDF is two or more pages long
- **THEN** every page after the cover renders the footer template with the page number and total pages
- **AND** the footer text matches the format "Page X of Y · sc0red.com"

#### Scenario: Cover page has no running header

- **WHEN** the PDF cover page is rendered
- **THEN** the page does not show the running header that appears on subsequent pages

### Requirement: Authentication via short-lived signed URL token

The `/print/{analysisId}` route SHALL be protected by a signed URL token issued by the auth-gated `/api/export/pdf/{analysisId}` endpoint. The token is HMAC-SHA256 over `{analysisId, orgId, expiresAt}` with a TTL of 60 seconds, signed by a per-environment secret stored in AWS Secrets Manager. The print route validates the token's HMAC, expiry, and analysisId match before rendering. Invalid or expired tokens result in 401.

#### Scenario: Valid token renders the print page

- **WHEN** the headless browser navigates to `/print/{analysisId}?t={validToken}`
- **THEN** the route validates the HMAC, confirms not expired, confirms analysisId match
- **AND** renders the print layout

#### Scenario: Expired token returns 401

- **WHEN** a token is older than 60 seconds
- **THEN** the print route returns 401
- **AND** does not render the analysis content

#### Scenario: Token for a different analysis is rejected

- **WHEN** a valid (non-expired) token contains analysisId `A`
- **AND** the request URL is `/print/B?t={token}`
- **THEN** the print route returns 401

### Requirement: ExportPDFButton shows loading state and triggers download

The `ExportPDFButton` component SHALL show a loading indicator from click until the PDF download triggers. After 5 seconds in flight, the button SHALL update its label to indicate continued progress ("Still working…"). After 30 seconds, the button SHALL surface an error Toast and reset to idle. On success, the response Blob SHALL be converted to a download via `URL.createObjectURL` and a programmatically-clicked anchor with the response's `Content-Disposition` filename.

#### Scenario: Button shows spinner during the 2–5s render

- **WHEN** the user clicks the Export PDF button
- **THEN** the button is disabled and shows a spinner with "Generating PDF…" within 200ms
- **AND** stays in that state until the response arrives

#### Scenario: Successful render triggers download

- **WHEN** the API responds with `Content-Type: application/pdf` and a Blob body
- **THEN** the file downloads using the filename from the `Content-Disposition` header
- **AND** the button returns to idle state

#### Scenario: Error response surfaces as Toast

- **WHEN** the API responds with a non-2xx status or the network request fails
- **THEN** a Toast error is shown
- **AND** the button returns to idle state ready for retry

### Requirement: PDF render emits the existing analytics event

The `sc0red_cta_rendered_in_pdf` event from the existing analytics pipeline SHALL continue to fire when an analysis with opportunities is exported as PDF. The event payload (`event_id`, `event_type`, `analysis_id`, `opportunity_count`, `source: "pdf"`, `user_id`, `org_id`) is unchanged.

#### Scenario: Analysis with opportunities is exported

- **WHEN** the user exports an analysis that has at least one opportunity
- **THEN** a `sc0red_cta_rendered_in_pdf` event is logged to the analytics CloudWatch log group
- **AND** `opportunity_count` reflects the count of opportunities in the rendered PDF

#### Scenario: Analysis without opportunities is exported

- **WHEN** the user exports an analysis that has zero opportunities
- **THEN** no `sc0red_cta_rendered_in_pdf` event is logged (matches the current pipeline's behaviour to avoid polluting funnel queries)
